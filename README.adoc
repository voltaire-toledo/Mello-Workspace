== 🎯 Overview & Philosophy

*Mello-Workspace (MWS)* bridges the gap between intent and action. Designed for developers, power users, and neurodivergent workflows (ADHD focus management, time-blindness mitigation), MWS provides consistent muscle memory, multi-monitor window control, intelligent text replacements, and hardware-accelerated context routing.

Unlike traditional launchers, MWS acts as an ambient automation layer that dynamically adapts across local displays, multi-monitor setups, and remote sessions (RDP/Hyper-V).

[TIP]
====
MWS eliminates hardcoded absolute paths by resolving applications dynamically through Windows COM `shell:AppsFolder` namespaces and standard Windows environment variables.
====

== 🚀 Installation & Setup

MWS provides streamlined installation methods tailored for both rapid deployment and active development.

=== Installation Method Comparison Matrix

[cols="^1,^1,2,2", options="header"]
|===
| Method | Target Use Case | Provisioning Actions | Deployment Location

.1+| *PowerShell One-Liner*
| Standard User / Quick Deploy
| Downloads latest zip, fetches official AutoHotkey v2 into `ahkbin/`, creates automatic backups, and registers Start Menu shortcut.
| `%LOCALAPPDATA%\Mello-Workspace`

.2+| *Git Clone & Local*
| Power User / Customizer
| Clones full Git history, runs `Mello-Workspace.ps1` locally, provisions missing `ahkbin/` runtime, and creates Start Menu shortcut.
.2+| Current Git Repository Directory

| Contributing Developer
| Provisions pre-commit hooks, validates environment via `setup-dev.ps1` or `task setup`, and symlinks custom functions.
|===

=== Method 1: PowerShell Command-Line Quick Install (Recommended)

Install and configure Mello-Workspace directly from PowerShell without manual cloning. This downloads the latest archive, provisions AutoHotkey v2 binaries into `ahkbin/`, configures the Start Menu shortcut, and starts the workspace.

[source,powershell]
----
# Launch PowerShell and run the remote installation one-liner:
irm https://raw.githubusercontent.com/voltaire-toledo/Mello-Workspace/main/Mello-Workspace.ps1 | iex <1>
----
<1> Automatically invokes `Install-FromUrl`, backs up any previous installation to `%LOCALAPPDATA%\Mello-Workspace\backup-*`, downloads dependencies, and registers the application.

[NOTE]
====
The installer stores application files in `%LOCALAPPDATA%\Mello-Workspace` and registers a clean shortcut under `Start Menu > Programs > Mello`.
====

=== Method 2: Git Clone & Local Script Execution

For users who prefer managing the repository via Git:

[source,powershell]
----
# 1. Clone the repository
git clone https://github.com/voltaire-toledo/Mello-Workspace.git
cd Mello-Workspace

# 2. Run the deployment script locally <1>
.\Mello-Workspace.ps1

# 3. (Alternative) Launch directly with AutoHotkey v2 <2>
.\ahkbin\AutoHotkey32.exe .\Mello-Workspace.ahk
----
<1> When executed locally, `Mello-Workspace.ps1` detects the repository workspace, fetches required runtime binaries into `ahkbin/` if missing, sets up Start Menu shortcuts, and starts MWS.
<2> Direct invocation when development binaries are already in place.

=== Method 3: Developer Setup via Taskfile

If you are contributing or customizing features, initialize your local environment using the included developer script or `task`:

[source,powershell]
----
# Run developer provisioning and git pre-commit hook setup
.\scripts\setup-dev.ps1

# Or run using Task
task setup
----

[%collapsible]
====
Core system hotkeys are `#SuspendExempt`, ensuring you can always reload, edit, or recover the script even when global hotkeys are paused.

| kbd:[Ctrl+Alt+Win+S]
| Toggle Suspend
| Temporarily suspends or resumes hotkeys. Tray icon turns red when paused.

| kbd:[Ctrl+Alt+Win+R]
| Reload MWS
| Instantly restarts and recompiles the AutoHotkey script.

| kbd:[Ctrl+Alt+Win+E]
| Edit Code
| Opens the active script in your preferred editor.

| kbd:[Ctrl+Alt+Win+F3]
| WindowSpy

| kbd:[Ctrl+Alt+Win+F12]
| System Sleep

.3+| *Navigation*
| kbd:[Ctrl+Alt+Win+F]

| kbd:[Win+F]

== ⚙️ Customization & Extensibility

MWS is architected to keep your personal configurations clean and separated from version control.

[source,autohotkey]
----
; Custom overrides in custom/.mslrc.ahk or custom/_custom_functions.ahk

; Example: Add a custom workspace shortcut
^!j::MsgBox("Custom workspace action executed!")

; Example: Personal snippet
:*::myemail::developer@domain.com
----

[IMPORTANT]
====
Do not modify core files in `lib/` directly for personal macros. Instead, add your routines to `custom/_custom_functions.ahk` or `.mslrc.ahk`. These files are ignored by git and will never conflict with upstream updates.
====
